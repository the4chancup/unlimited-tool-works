    The Music player's three below come from reading the controls of Rigdio v2.2.0, the music player the cups use today.

    Chaoshorn and the score

    From: worklog 10.0i; plans/music_player.md "Playback semantics"

    Rigdio's Chaoshorn presses every goalhorn button, so it scores a goal for each player and one for the Standard Goalhorn: the scoreboard jumps by the roster size plus one, and each player's horn is chosen as it would be for that goal.

    Should Studio's Chaoshorn score those goals too?

    A button after its song ends

    From: worklog 10.0i; plans/music_player.md "Playback semantics"

    When a goalhorn with end stop, or a victory anthem, plays to its end, Rigdio's button stays pressed. The next press only releases it, with no goal and no sound, and the press after that scores and plays.

    Do streamers rely on that extra press?

    title.log and chants

    From: worklog 10.0i; plans/music_player.md "Playback semantics"

    Rigdio writes title.log, which the OBS overlay shows, for anthems, victory anthems and goalhorns, but never for a chant.

    Should the overlay show a chant's title too?

    A team file imported onto another team brings its manager ID

    From: a member's PES 2021 save, 2026-11-12

    The Save editor imports a Team TOML onto the open team and writes the file's manager_id as it is. A file exported from team 876 and imported onto team 886 leaves both teams naming coach 876; in that save, every other team's manager ID is its own team ID. On the same import, a player's base copy ID is turned into the target's own, but the manager ID is not.

    Does the game mind two teams sharing one coach record?

    When the file's manager ID equals the file's team ID, should the import give the target its own?

    Three texts the build changed and the drafts never took

    From: the rereading's fourth wave (f32b3ab5, 2026-11-13) and 17a1148c, which brought the drafts in step

    The fourth wave of the rereading reworded the windows' texts, and a later commit brought the drafts in step from the four sidekick reports' lists. One list left out the Ruleset editor's texts, and the lead did not check the lists against the commit, so two texts in the drafts still read as before. A third is a behaviour: on 2026-11-12, after a member's report, Choose file… stopped opening in the selected version's save folder (58892900), and the draft's File menu still says it does; the draft's own Choose file dialog already follows the new rule.

    1. The help line under Rating stats (Ruleset editor, General page)

    Draft: A player's rating is the highest of these; it picks his tier. What a stat may sit at is the target, the warning band and the stat total, not the rating. Build: A player's rating is the highest of these stats, and it picks his tier. The values a stat may take come from its target, the warning band and the stat total, not from the rating.

    2. The tooltip on the player's Name count (Save editor, the strip over the player page)

    Draft: Up to 61 bytes. A plain letter takes one byte, an accented letter two or more, and a colour code ten Build: Up to 61 bytes: one for a plain letter, two or more for an accented letter, and ten for a color code (typed as \x11c and eight hex digits).

    3. Choose file…'s tooltip (Save editor, File menu)

    Draft: Opens in the selected version's save folder when it exists Build: Pick a save file, starting in the folder of the save opened last (or else of the newest save found)
