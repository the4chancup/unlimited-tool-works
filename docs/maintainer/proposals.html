    P40: The Music export editor reorders its players

    From: the RigDJ audit (10.0h, 2026-10-27); plans/music_export_editor.md "What the editor does"

    The editor lists and writes the players in the file's order, which is the order of Rigdio's buttons. 27 of the 50 RigDJ-written exports on your machine have their players out of sorted order, so managers reorder them by hand in a text editor; RigDJ re-sorted them on every load.

    Adds: up and down buttons (or a drag) on a player in the slot list, so a manager sets the button order the streamer sees without leaving the editor.

    Costs: two buttons beside Rename and Delete, and the drag the song rows already plan, reused for the slot list. Nothing new in the format.

    P41: The Kit config editor shows what a collar, shorts model or pattern looks like

    From: the Kit Manager audit (12.0a, 2026-10-27); plans/kit_config_editor.md "Preview panel"

    Kit Manager's preview was a catalogue: one prerendered picture per collar (1–106), shorts model (0–17), shirt pattern (0–13), sleeve type and shirt model, shown as the field changed. The planned preview draws the kit's colors, positions and real textures, so it drops the one thing Kit Manager's showed: what collar 37 looks like before you pick it.

    Adds: a thumbnail beside the Collar, Winter collar, Shorts model and Shirt pattern fields, or a gallery to pick from, for the kit maker who knows the look and not the number.

    Costs: the pictures themselves, which Kit Manager's bitmaps cannot supply (PES 2016's models, 51 MB, not ours to ship): renders of each version's stock collars and shorts, made once per version (up to 131 collars on PES 2021), plus a gallery widget.

    P42: The color picker's hex field takes Kit Manager's spellings too

    From: the Kit Manager audit (12.0a, 2026-10-27)

    Kit makers paste colors from the tools they used with Kit Manager, which accepted 0xRRGGBB and bare RRGGBB (and nothing else, not even #RRGGBB). The shared color picker's hex field is specified only as the TOML's #RRGGBB.

    Adds: the hex field accepts #RRGGBB, 0xRRGGBB and RRGGBB alike in every tool that uses it, so a value pasted from an old habit is taken instead of refused.

    Costs: one parse with three prefixes in color_tools. The field still shows #RRGGBB.

    P51: A button that goes back to the version an update replaced

    From: the first plan (2026-09-13, plans/core/distribution.md "Rollback"), written after Red, which keeps the whole old folder when it updates. You never asked for it, and on 2026-11-12 didn't remember doing so.

    Built already: Update now leaves the program it replaced in the bundle's old/ folder, one version deep. A member can go back by hand: close the program, and copy the program file from old/ over the one in the bundle's folder.

    Adds: a "Roll back to previous version" button in the settings menu, which swaps the two programs and restarts, for a member whose new version is broken. No member can reach it in 0.0.2: 0.0.1 cannot update itself, so the first old/ folder appears when 0.0.2 updates to its successor, and the button that matters then is the successor's.

    Costs: the plan's three lines leave most of it open, each a thing to build and for a member to learn:

    • a confirmation, since the program restarts;
    • what the button reads after a rollback, when old/ holds the newer program: naming the version needs a version file written beside the program in old/;
    • the state after the swap when a tool's close prompt cancels the restart: a reminder like Update ready, and no update offered meanwhile;
    • only the program file goes back: the launchers and the readme stay the newer version's, and a launcher passing an option the older program lacks fails.

    A cheaper cover for the same case: one sentence in the help's Updates chapter giving the steps by hand above.

    P55: The Compiler's help as two topics

    From: the text rereading of 2026-11-13 (worklog 0.0.2-text)

    The Compiler's help is one topic, "Running from a terminal", of about 1,200 lines. Two thirds of it is what goes in an export and what each file becomes, which a member using the window needs as much as one using a terminal, and would not look for under that title. The part a member opens the page for (the exports folder, --export, --no-deploy, the modes, the exit codes) starts after 750 lines of per-file rules.

    Adds: two topics, each findable by its title:

    • "What goes in an export", from "What compile builds" through "Kit config values the game ignores or cannot hold";
    • "Running from a terminal": the commands, which exports a run reads, install errors, upgrade-dpfl, the modes, multicpk_mode, exit codes, the aesthetics patch.

    Costs: the text moves between two files, and the tool's topic list and the help tests gain an entry. A link or search hit a member saved to the old topic's second half lands on the new one.

    P56: The window can say the game's Edit mode is closed

    From: the text rereading of 2026-11-13

    While the PES the save belongs to is running, a compile skips writing the save unless it is run with --edit-mode-closed. The window's Compile button cannot add that option, so from the window the only way to get the save written is to close the game, and the message for a skipped save now says so.

    Adds: when a compile from the window skips the save for that reason, the message (or a dialog) offers "Edit mode is closed, write the save", which writes the save alone, as the option would.

    Costs: one more confirmation, whose wrong answer loses the save's changes when the member leaves Edit mode (the reason the option exists), plus a save-only run from the window and its tests.

    P59: After Select all similar players, the list scrolls to the player

    From: the build of Select all similar players (worklog 0.0.2-similar, slice 1b), 2026-11-22

    With Every team picked, Select moves the list to All teams, thousands of rows, and the list keeps its scroll, as the approved draft does. The player the window was opened on, now selected, can be far off screen.

    Adds: after Select, the list scrolls to him, as it does when the selection moves by the arrow keys. With his team picked under Look in, he is usually in view already, and nothing moves.

    Costs: a line in the build and the draft. The list may jump when Select is pressed.
