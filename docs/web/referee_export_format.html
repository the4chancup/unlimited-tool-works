The referee export in the UTW format

The referee export is the folder whose name starts with refs (such as refs Spring): the referees' faces, boots and gloves, and the list saying which referee fills which of the game's 35 referee slots. Unlimited Tool Works compiles it in the UTW format, which lays it out like a team's export. This page shows what changed from the previous layout (the AET format, the one Red compiles) and how an old referee export is upgraded.

In one sentence: refs.txt becomes players.txt, and each referee's face, boots, gloves and common subfolders are folded into the referee's own folder. Everything else stays where it was.

What is different

WhatPrevious (AET format)New (UTW format)
The slot list refs.txt at the root. Some older exports call it Refs list.txt. players.txt at the root, the same file a team's export may use. It is required: the referees' folders carry no numbers, so the list is the only place that says who fills which slot.
Inside a referee's folder Four subfolders: face, boots, gloves and common. No such subfolders. The models, textures and face.xml stand directly in the referee's folder, exactly as in a team player's folder.
How a file's kind is told By the subfolder it is in: whatever lies in boots is boots. By the file's own name (boots.fmdl, oral_boots_win32.model, glove_l.model), as for a team player.
Where the referees' folders stand In Players/. The oldest exports (the Refs list.txt ones) have them directly in the export. Always in Players/.
A model several referees share Copied into each referee's folder. Copied as before, or kept once in a shared Boots/, Gloves/ or Faces/ folder at the root and linked from a referee's folder with an empty file named after it (Crocs.boots), as in a team's export.
The referee marker on PES 18-21 Red wrote ref_marker.dds into the game's own dt00_x64.cpk, after asking. The marker goes into the referees' CPK and no game file is written. See "The referee marker" below.

What stays the same

  • The name. The export's name starts with refs. It takes no Full or Midcup word, unlike a team's export.
  • The 35 slots. The game has 35 referee slots and picks among them for each match. Listing one referee under several slots is still how you make that referee more frequent, and one listed once is rare.
  • ref_marker.dds at the root, same file, same place.
  • Common/ and, on PES 15-17, Common/refkit/: the referees' body. Its files replace the built-in ones of the same name, and the built-in files you do not replace stay.
  • No savefile. A referee has no record in the save, so neither the upgrade nor the compile of a referee export reads one.
  • The result in game. The referees compile into a CPK of their own, as before.

The slot list, players.txt

One line per slot: the slot's number, a space, then the name of the referee's folder in Players/.

01 tsuoffside
02 tsuoffside
03 tsuoffside
04 galosengen
05 galosengen
06 linesman bob
...
35 galosengen
  • Slots run from 01 to 35, each listed once at most. The list need not fill all 35.
  • The same folder may appear on as many lines as you like.
  • The folder's name is everything after the number, spaces included. Upper and lower case do not matter.
  • Plain text saved as UTF-8. Blank lines are skipped. There are no comment lines.
  • Every folder in Players/ must be listed at least once, and the list must name at least one referee.

An old refs.txt has the same lines, so the upgrade carries it over unchanged apart from the file's name and two-digit slot numbers.

Upgrading an old referee export

The referee export takes no savefile, so quick_upgrade.bat lists it as not upgraded. Upgrade it with its own command, from a console opened in the folder that holds UTW.exe, with your export's name in place of refs Spring:

UTW.exe export-upgrader upgrade "old_exports\refs Spring" -o exports

The old export is never changed. The upgraded copy is written into exports under the same name. What the upgrade does:

  • writes players.txt from refs.txt (or from Refs list.txt when there is no refs.txt), and leaves the old list out of the copy;
  • folds each referee's face, boots, gloves and common subfolders into the referee's folder, without renaming any file;
  • keeps a file once when two of those subfolders hold it with the same content;
  • rewrites the paths inside the referee's face.xml, .mtl and model files so they still point at the moved files;
  • moves referee folders that stood directly in the export into Players/;
  • when a referee uses a texture from the export's Common/, adds a small link file for it in the referee's folder (whistle.dds.common), as a team player's folder has;
  • carries ref_marker.dds and Common/ over, and drops a Team Note file with a warning, since nothing ever read one in a referee export.

The upgrade never guesses. In the cases below it names the file, writes nothing and ends with an error, so you fix the old export and run the command again:

In the old exportWhy it stops
Two of a referee's subfolders hold a file of the same name with different content, or two textures of the same name in different formats (hair.dds and hair.ftex) Only one of the two can stand in the flat folder, and the upgrade cannot know which.
A face, boots, gloves or common folder inside one of those four (Face/face/) Once folded, the referee's folder would again hold a subfolder of one of the four names, which is the old layout.
A model in a referee's common that none of the referee's face.xml files names It was never shown in game, and in a flat folder it would become part of the face.
No refs.txt and no Refs list.txt There is no slot list to carry over.
A slot list that is not valid UTF-8 text The referees' names cannot be read.

The compile does not read the old layout. A referee folder that still has one of the four subfolders is refused there with the error player_layout_proto, which tells you to upgrade the export.

Making one directly in the new format

Build each referee's folder as you would a team player's: every model and texture directly in it. Then write players.txt and put ref_marker.dds beside it. Three things differ from a team player's folder:

  • No number in the folder's name. tsuoffside, not 01 - tsuoffside: the slots come from players.txt alone.
  • A referee without a face model keeps the game's own head. A team player in the same case gets a blank face.
  • On PES 15-17, a referee whose face is a head only needs a body. Put an empty file named fpc_off in the folder and the compile dresses the referee in the refkit, the body in Common/refkit/ (shirt, shorts, socks, arms, and the boots and hands when the referee has no boots or gloves of their own). A referee whose face.xml already lists the body needs nothing.

The referee marker

ref_marker.dds is the picture the game draws flat on the ground with each referee. It stays in the export, in the same place, but it reaches the game differently:

  • PES 15-17: as before, it replaces a texture inside the referees' CPK.
  • PES 18-21: the referees' kits are given collar 77, and the referees' CPK holds a model for that collar which draws the marker. The game's own dt00_x64.cpk is no longer written, so there is no question to answer and nothing to back up.

Collar 77 is therefore reserved for the referees on every version. A team's kit that uses it is left out at compile time and reported (kit_collar_reserved), because its players would be drawn with the referees' marker.

An export without ref_marker.dds simply has no marker.
